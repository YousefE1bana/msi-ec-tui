# MEC v1.1.0

MEC brings the approved dense terminal interface to every production screen,
with keyboard and mouse controls sharing one staged, reviewed and explicitly
confirmed execution path. MSI Dark remains the default.

## New and improved

- Dashboard, Performance, Fans, Battery, Devices, Profiles, Diagnostics and
  Settings use a common status strip, workspace and shortcut footer. Help,
  command palette, reviews and result notices follow the same visual system.
- Mouse selects controls, edits supported values, opens reviews and confirms
  only through the explicit Apply button. Selecting a profile or telemetry
  card never executes a hardware command. Numeric and keyboard controls remain.
- Optional Arctic Midnight and Graphite Violet themes, alongside MSI Dark,
  Terminal and Light. `--theme` affects this session; palette choices persist.
- About MEC shows the build version, real device/support data and project
  credits. Open Settings → ABOUT MEC or P → About MEC.
- Explicit update discovery through About or `mec update-check`, using GitHub
  with verified TLS, a bounded response and five-second timeout. No startup
  check, telemetry upload or automatic update installation.
- Inspect-first installer, terminal desktop launcher, original MEC icon,
  public documentation and 47 real physical-device screenshots.
- Responsive menu/palette hit regions, readable table columns, and reliable
  three-second success / six-second failure notice expiry.

## Safety and permissions

The existing capability/support checks, restricted write boundary, mandatory
readback and settling retries, serialized mutations, profile preflight,
transactions and rollback are preserved. No alternate mouse executor exists.
Unsupported hardware remains READ-ONLY. READY does not grant Linux write
permissions: the desktop launcher runs as the current user, and root-owned
sysfs controls can reject writes. No privilege helper, permission-changing rule
or automatic kernel-driver installation is shipped.

## Validation and compatibility

The complete automated suite passed: **1,748 tests, zero failures**, including
keyboard/mouse confirmation, profiles, rollback, unavailable telemetry,
READ-ONLY and responsive/zero-area rendering. Formatting, strict Clippy, release
build, Cargo packaging, installer syntax and packaging/documentation tests passed.

Physical production QA on **MSI GF63 Thin 11UC / EC 16R6EMS1.107**, Ubuntu
26.04.1 x86_64 with upstream msi-ec 0.13 and an existing signed Secure Boot
driver, verified Shift Mode, Fan Mode, Cooler Boost, battery limits, Webcam,
Webcam Block, Backlight and Silent profile through both keyboard and mouse.
Staging/review and Cancel changed no exposed hardware state. All nine captured
control fields were restored exactly. A normal-user Apply was rejected without
changing hardware. See the [physical validation record](https://github.com/YousefE1bana/msi-ec-tui/blob/v1.1.0/docs/physical-validation.md).

Release assets target **x86_64 and aarch64 glibc Linux**, requiring glibc 2.39
or newer. `.deb`, `.rpm` and portable archives are package formats, not a claim
of physical validation on every distro or on aarch64 MSI hardware. Kernel,
firmware, driver support and permissions remain machine-specific. The installer
also requires Python 3.12+. AUR metadata is supplied; no AUR publication is claimed.

## Known limitations

- On the validation laptop, Silent's eco Shift Mode coincided with Super Battery
  reading On although Silent sends no Super Battery command. The cause is
  unproven. Inspect the full current state after eco/profile changes; Super
  Battery was explicitly restored to its captured Off state during QA.
- Fan telemetry is percentage/raw data, **not RPM** or proof of airflow.
  Cooler Boost state/readback passed; this QA did not verify acoustic response.
- Physical rollback fault injection and other-distro package installations were
  not performed. Controlled fixture tests cover transaction failures/rollback.
- Fn/Win Key controls remain informational where no typed mutation is supported.
- SHA256SUMS provides artifact integrity, not publisher-signature authentication.

## Installation and upgrade

Download and inspect the installer before running it:

```sh
curl -fsSLO https://raw.githubusercontent.com/YousefE1bana/msi-ec-tui/main/install.sh
less install.sh
bash install.sh --dry-run
bash install.sh --version 1.1.0
mec --version
mec doctor
```

Existing config and profiles are preserved. Driver/DKMS and Secure Boot/MOK
setup remain explicit manual steps. Read the [installation guide](https://github.com/YousefE1bana/msi-ec-tui/blob/v1.1.0/docs/installation.md)
and [permissions guidance](https://github.com/YousefE1bana/msi-ec-tui/blob/v1.1.0/docs/troubleshooting.md).

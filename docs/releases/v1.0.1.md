# MEC v1.0.1

A patch release fixing false hardware verification failures and the
`mec --version` flag. No hardware behavior changes beyond correct
verification of writes that already succeeded.

## Fixed

- False hardware `VerificationFailed` results caused by immediate
  EC/sysfs readback after a successful physical write. The EC-backed
  attribute can still show the stale value for a fraction of a
  millisecond after the write lands.
- Bounded readback settling: one immediate read plus up to 5 delayed
  polls at 2 ms intervals (approximately a 10 ms maximum window). A
  write succeeds as soon as readback proves the requested state.
- The hardware write itself still occurs exactly once; only readback
  polls repeat.
- Structural post-write read errors (vanished target, denied access,
  malformed value, I/O failure) still fail immediately and are never
  retried.
- `mec --version` now works through Cargo/Clap metadata and prints the
  package version.

## Physical validation completed on

- MSI GF63 Thin 11UC
- EC firmware 16R6EMS1.107
- upstream msi-ec 0.13

Confirmed physical controls:

- keyboard backlight
- webcam
- webcam block
- cooler boost

Cooler Boost produced an audible physical fan response. Note that
`realtime_fan_speed` telemetry did not reflect that response reliably
on this machine, so telemetry must not be treated as physical RPM or
actual Cooler Boost airflow.

Not yet physically tested: battery threshold, shift mode, fan mode,
profile transaction, and TUI mutation paths. Those remain covered by
automated fake-sysfs tests.
